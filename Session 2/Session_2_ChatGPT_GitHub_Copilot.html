Prompt sent to ChatGPT:

I am building a Flipkart-style React product card. Here is my component:

[paste the component above]

My VS Code/ESLint warning is:
"img elements must have an alt prop"

Explain why this warning occurs, whether it affects accessibility, and show me the corrected component. Keep the explanation beginner-friendly.

Explanation: The image is missing an alt attribute. Alternative text helps screen readers understand the purpose of an image and also provides useful text when an image cannot be displayed.

Corrected version:

function ProductCard({ image, title, price }) {
  return (
    <div className="product-card">
      <img src={image} alt={title} />
      <h2>{title}</h2>
      <p>₹{price}</p>
    </div>
  );
}

export default ProductCard;

Important: The exact warning shown depends on the ESLint/accessibility rules installed in the React project. When using ChatGPT for debugging, always provide the actual error or warning text instead of guessing.

Task 3 – Prompt for Refactoring a Zomato-Style Restaurant Listing

Prompt:

I have a React component for a Zomato-style restaurant listing that fetches restaurant data directly inside the component. Refactor it to use a custom reusable hook called useRestaurants.

Requirements:
1. Move the data-fetching logic into useRestaurants.js.
2. The hook should manage restaurants, loading, and error state.
3. The hook should fetch data from /api/restaurants/ using fetch.
4. The component should only handle rendering the restaurant list and displaying loading/error states.
5. Do not use unnecessary dependencies.
6. Keep the code beginner-friendly and explain what each part of the custom hook does.
7. Return both useRestaurants.js and the refactored RestaurantList.jsx.

Also explain why moving the fetching logic into a custom hook makes the code more reusable.

Example refactored hook:

import { useEffect, useState } from "react";

function useRestaurants() {
  const [restaurants, setRestaurants] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState("");

  useEffect(() => {
    fetch("/api/restaurants/")
      .then((response) => {
        if (!response.ok) {
          throw new Error("Failed to fetch restaurants");
        }
        return response.json();
      })
      .then((data) => setRestaurants(data))
      .catch((error) => setError(error.message))
      .finally(() => setLoading(false));
  }, []);

  return { restaurants, loading, error };
}

export default useRestaurants;

Task 4 – Refactor YouTube Video Fetching with useVideos

Before refactoring: the component contains both the UI and the API-fetching logic.

import { useEffect, useState } from "react";

function VideoList() {
  const [videos, setVideos] = useState([]);

  useEffect(() => {
    fetch("/api/videos/")
      .then((response) => response.json())
      .then((data) => setVideos(data));
  }, []);

  return (
    <div>
      <h2>YouTube Videos</h2>
      {videos.map((video) => (
        <p key={video.id}>{video.title}</p>
      ))}
    </div>
  );
}

export default VideoList;

Copilot instruction:

Refactor this React component. Move all video fetching logic into a reusable custom hook called useVideos. The hook should manage videos, loading, and error state. Keep VideoList focused only on displaying the UI. Return the complete useVideos.js and VideoList.jsx files.

useVideos.js:

import { useEffect, useState } from "react";

function useVideos() {
  const [videos, setVideos] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState("");

  useEffect(() => {
    fetch("/api/videos/")
      .then((response) => {
        if (!response.ok) {
          throw new Error("Failed to fetch videos");
        }
        return response.json();
      })
      .then((data) => setVideos(data))
      .catch((error) => setError(error.message))
      .finally(() => setLoading(false));
  }, []);

  return { videos, loading, error };
}

export default useVideos;

Refactored VideoList.jsx:

import useVideos from "./useVideos";

function VideoList() {
  const { videos, loading, error } = useVideos();

  if (loading) {
    return <p>Loading videos...</p>;
  }

  if (error) {
    return <p>Error: {error}</p>;
  }

  return (
    <div>
      <h2>YouTube Videos</h2>
      {videos.map((video) => (
        <p key={video.id}>{video.title}</p>
      ))}
    </div>
  );
}

export default VideoList;

Result: The component is now easier to read because fetching, loading, and error-handling logic is reusable in useVideos.

Key Learning

ChatGPT and GitHub Copilot can significantly accelerate development by explaining errors, generating starter code, suggesting refactors, and helping create reusable hooks. However, AI-generated code should be treated as a suggestion rather than automatically trusted code. The developer remains responsible for reviewing, testing, securing, and understanding the final implementation.
